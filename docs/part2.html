Part 2: our own 4B citation edit

We used Astra's recipe on Qwen3.5-4B for a failure it really has: citations that point to the wrong place. The recipe transferred mechanically. One direction, two layers and the lowest dose raised the share of citations that hold by about 3.5 points, and it beat a random direction of the same size. The statistics need careful reading. So does what the edit actually is.

Reviewed by GPT-6 Astra (11 November). Astra recomputed every headline figure and re-checked all 3,276 citations of the twelve fresh runs, and found no discrepancies. Its corrections, now applied on this page:

  • The intervals below resample items, with each arm's runs pooled. They leave out run-to-run variation. Allowing for it as well, Astra's sensitivity check gives edited − base of about −0.1 to +7.6 points (held-out −1.4 to +11.9). The gain is likely, not settled.
  • The held-out items were kept out of building the direction, but they did inform some exploratory choices (which token spans to try). They are not an untouched test set.
  • The control is one random edit, repeated over four seeds. The claim is that the edit beat this control, not that any random edit does nothing.
  • That we found no "this citation will miss" direction does not show that none exists.

A replication with fresh seeds, a second day's data and a tool-calling check is running, together with a round of improvements in response to the review.

In short

  • Citations that hold: base 89.7%, random control 88.4%, edited 93.1% (four runs per arm). Edited − base +3.5 points, 95% interval +1.1 to +6.2. About a third of the misses go.
  • The test we planned was two runs per arm. By the rule we wrote before running it, the result was "not shown". We then declared two more runs per arm, fixed their number, and ran them. The four-run result above comes from that extension, decided after we saw the first.
  • The edit does not make the model pass the whole benchmark more often: 2 of 4 runs, the same as the base.
  • It is not a "be careful" switch. It is a small re-weighting of words in the last two layers. That direction also carries the end-of-answer token, so higher doses produce answers that never end.

Why a different target

We first checked whether the 4B loops the way the 0.8B does. Under the post's settings (C1), on 128 practice problems, only 3 answers (2.3%) reached the 32,768-token cap, and 122 of 128 (95.3%) were correct. The 0.8B under the same settings had 85 of 96 at the cap. Astra's edit would have almost nothing to fix on the 4B.

Data: data/part2/base_4b_math_practice.json.

So we picked a failure the 4B does have, in a private agent benchmark.

The benchmark (private) and the failure

A review agent reads 70 items, plus 11 injected test items. It may call read-only tools, and for each item it returns a JSON decision with a list of evidence. Each piece of evidence is a citation: a ref, which is a path into the item's JSON (such as text), and a quote. A checker looks up the path. The citation holds if the quoted words are there. Seven run-level checks (G1–G7) decide whether a run passes. One of them (G5) is about citations.

From two earlier runs of the base 4B we took every citation of an item: 583 citations in 139 final answers. 492 cite the item: 415 hold and 77 do not. Most misses are of one kind. In 67 of the 79 misses the quote is right and it is in the item, but the path points elsewhere (for example facts[0].text where the sentence sits in text). The 4B's misses are wrong paths, not badly copied quotes.

Data: data/part2/contrast_set_and_survey.json.

Before reading any internal state, we split the items: an item is held out if sha256(key) mod 5 < 2. That gave 32 held-out items and 38 practice items. Directions were built on practice items only.

Is there a "this citation will miss" direction?

We found none. We read the base model's hidden states over every citation and built difference-of-means directions on practice items. Then we measured how well each separates misses from hits on held-out items (AUC; 0.5 is chance):

Where the path is decided, nothing separates the two. At the quote, the separation is already there at layer 0 (0.97), before any computation. That is the words themselves: misses mostly quote a prose sentence, and held citations mostly quote field values such as paths and numbers. The model is not unsure when it misses, either. At the fork, it gives the wrong path's token a median log-probability of −0.16 and the right one −2.6. These are confident errors about the JSON layout.

The recipe, applied anyway

A direct test was cheap, so we built four edit families with Astra's rules:

  • direction: a per-layer difference of means (misses minus held citations) on practice items;
  • layers: the MLPs that write most of that contrast;
  • columns: the top 165 by (write strength along u) × (activation contrast). That is the same 1.79% of the MLP width that Astra's 64 columns were on the 0.8B;
  • edit: W ← W0 − dose·u(uᵀW0) on those columns of mlp.down_proj;
  • control: a random unit direction orthogonal to every u, on the same columns, scaled so the weights change by the same amount (Frobenius norm).

We wrote a rule for choosing the family before running the screen. The screen reads the practice answers teacher-forced. At each fork it measures S, the change in log p(right path token) − log p(wrong path token). Family F1 (the tokens from the path to the end of the citation, matched inside each answer, layers 29 and 31) passed the rule and won. Its random control moved S the wrong way:

What F1's direction is. Read through the output layer, its "miss" side is prose words and the end-of-answer token (" day", " last", " not", " one", <|im_end|>). Its "held" side is JSON punctuation and pieces of field names. It is a lexical direction, as the survey warned. At dose 1 it changes the two tensors by 0.70% and 0.93% (MIT's edit changed its two by 8–11%).

The full test, with a random control

All 70 items, the same benchmark and settings as the earlier runs. Fresh base runs ran in the same jobs as the edits. Before any of these runs we wrote the rule for "it worked":

  1. every edited run holds a larger share than every fresh base run and every control run;
  2. on the held-out items, edited − base and edited − control are positive, with 95% intervals above zero (bootstrap over items, 10,000 draws);
  3. the edited runs are no worse than the base on valid answers, and pass the citation check G5.

By our own rule, the planned test is "not shown".

The extension: two more runs per arm, declared after the first result

Two questions were left open, and both were about noise that two runs could not settle: is the held-out gain real, and does the answer that never ends come with the edit? We declared two more seeds per arm, fixed that number, and ran them. Read the following with that order in mind.

  • The extension runs on their own show the same sign, with a smaller gain over the base: +2.4 points (−0.9 to +6.1). Against the control: +4.6 (+0.9 to +8.5). On their own, they do not separate the edit from the base.
  • Every one of the four edited runs (92.4–94.4%) is above every fresh base run (87.8–90.7%) and every control run (86.5–90.6%).
  • Misses fell by about a third: 113 of 1,092 citations (base), 130 of 1,121 (control), 73 of 1,063 (edited). The clearest single change is that a bare facts path nearly disappears.
  • The whole benchmark (checks G1–G6): the edited model passed in 2 of 4 runs, the fresh base in 2 of 4, the control in 1 of 4. Both edited failures were the same answer running to the cap. That happened in 2 of 4 edited runs against 1 of 10 runs without the edit (Fisher's exact test, one-sided, p = 0.18). Not settled.

How we read it. The citation effect is real and modest: about 3.5 points, a third of the misses. It reaches items the direction was not built from, and it beat a random direction of the same size. But the planned test did not show it, and allowing for run-to-run variation its interval touches zero. The evidence for it comes from an extension that we chose after seeing that result. And the edit does not make the 4B pass the benchmark reliably.

The edited direction costs four to eight times what a random direction of the same size costs. At dose 1 the cost is small: +0.40% perplexity, and six short-answer prompts gave the same answers token for token from the base, the edit and the control. In the benchmark, answer lengths matched the base except for the answers that never ended.

What the edit is, and what it is not

It is not a "quote exactly" or "be careful" direction. We found none in the 4B's states for this failure. It is a small lexical re-weighting in the last two MLPs (165 columns each, under 1% of each tensor's norm). For a quote of the item's sentence, it makes the 4B write paths that hold, most clearly text instead of a bare facts. The same direction carries the end-of-answer token. That is why answers stop ending at higher doses.

The obvious rival is one line in the prompt, such as "a quote of the item's sentence has the path text". We did not test it. It is the first thing to try before any weight edit of this kind.

Cost, against Astra's

The editor here was a Claude agent (Fable 5.2 in Claude Code) with its own scripts. It read the model's internals directly. Astra had a fixed budget of forward passes and no GPU in its kernel. So the two are not the same task. For scale: our 4B work took about 4.7 GPU hours in five jobs, and 12.75 hours of wall clock from the first entry to the last. Most of the GPU time went to benchmark runs, not to finding the edit. Astra's 50-pass run took 20.3 hours.

Data: data/part2/cost.json; Astra's run: the authors' run table.

What we did not check

  • One prompt set and one sampling setting (temperature 0.3). One random control direction.
  • The direction came from 14 practice answers in two runs. No other column counts or layers were tried for F1.
  • Doses 2–6 went through the 24-item screen only. F2–F4 went through the teacher-forced screen only.
  • The edit was served in bf16 from safetensors. No quantised copy was checked.
  • The regression check is small: five files and 18 prompts. There was no tool-calling set and no thinking-mode run.
  • The bootstrap treats items as the unit and pools each arm's runs. It does not model run-to-run variation separately.
